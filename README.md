# 生研观察 BioScope · v0.2.19

[打开公开网站](https://jimmy-ui456.github.io/bioscope-daily/) · [使用与项目结构入门](https://jimmy-ui456.github.io/bioscope-daily/guide.html) · [查看采集与发布状态](https://github.com/Jimmy-ui456/bioscope-daily/actions/workflows/pages.yml)

[2026-11-13验证记录](docs/VERIFICATION-2026-11-13.md)汇总当前中英对照、实际定时、原平台下载量核对和恢复测试；[10月30日记录](docs/VERIFICATION-2026-10-30.md)保留历史结果。数据均带有核对时点，不代表未来实时状态。

面向合成生物学、代谢工程与微生物制造的科研文献工作台。支持中英对照、基于摘要的自动中文解读、后台定时采集、原出版平台下载量排行和个人日报。

架构参考 [AIHOT](https://github.com/KKKKhazix/AIHOT) 的采集、整理、精选与成刊流程，本项目为独立轻量实现。无需安装 npm 依赖；Node.js 24 即可运行。

## 本地运行

双击 `启动预览.cmd`，或在本目录执行 `npm start`，打开 <http://127.0.0.1:4173>。

保持进程运行即可在关闭网页后继续定时采集，默认北京时间07:17；电脑关闭或休眠时本地任务不会运行。`SCHEDULE_ENABLED=false` 可关闭本地定时功能。

```powershell
npm.cmd run collect  # 立即采集一次并处理待解读文献
npm.cmd run worker   # 只运行定时后台，不启动网页
```

## GitHub 公开网站与无人值守更新

将仓库 Settings → Pages → Source 设为 GitHub Actions。`.github/workflows/pages.yml` 会先检查源码，每天 UTC 23:17（北京时间次日07:17）或手动触发时采集文献，将公开快照保存为 `dist/library.json` 并提交，再将 `dist/` 发布到 GitHub Pages。定时自动模型默认暂停，只有Actions Variable `LLM_AUTO_ENABLED` 精确为 `true` 且配置完整时才调用；文献采集与发布不受此开关影响。普通手动补采仍强制禁模。只有明确勾选“补采并最多翻译1篇”时，才允许最多1次模型请求，且仍受当日预算及既有回执限制。

这套云端流程不依赖个人电脑开机。[GitHub官方说明](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)指出定时任务可能延迟，繁忙时也可能丢弃，不能据计划时间断言已经运行。可进入 Actions → Collect research and publish website → Run workflow 手动补采；完成后核对运行摘要、失败方向、模型请求数和Pages发布结果。页面快照会标明手动补采或定时采集，并链接对应运行。变更云端定时时间需同时调整工作流 cron 和 `config/monitor.json` 的显示值。公开仓库长期不活跃时也应检查任务是否被平台停用。

Pages 只负责静态网页，Node.js 采集与模型调用由 Actions 执行。个人收藏与精选仍保存在每位访客自己的浏览器；不会上传访客的阅读数据。

## 模型配置入口

已准备低价的阿里云百炼北京地域 `qwen3.7-flash`，显式关闭深度思考；缺少密钥时不调用模型。GitHub的非秘密接口地址与模型名放在Actions Variables，API Key只放Secrets；本地可复制 `.env.example` 为 `.env` 后仅补密钥。2026-11-13北京时间21:43的[首次单篇验收](https://github.com/Jimmy-ui456/bioscope-daily/actions/runs/43436064175)尝试1次、有效结果0篇，维护者核对百炼审计状态为200；旧代码未保存具体校验原因。随后经明确授权于22:09[新增一次单篇试译](https://github.com/Jimmy-ui456/bioscope-daily/actions/runs/43440017171)，仍无通过结果，诊断为 `invalid_evidence`（解读或局限的证据未通过校验）。两次回执原样保留，当日尝试2次，不代表已确认真实账单金额。证据协议已改为后台提供原文片段编号并还原引文，仅完成离线验证，尚无该新协议的真实模型成功结果；自动模型保持关闭。

| 名称 | 内容 |
| --- | --- |
| `LLM_BASE_URL` | Actions Variables：`https://dashscope.aliyuncs.com/compatible-mode/v1`；不含 `/chat/completions` |
| `LLM_MODEL` | Actions Variables：`qwen3.7-flash` |
| `LLM_API_KEY` | 自己创建的百炼北京地域API Key；只放服务器环境或GitHub Secrets，不能放Variables |
| `LLM_AUTO_ENABLED` | 仅Actions Variable，默认 `false`；真实单篇验收成功后再设为 `true`，开启云端定时翻译 |

注册、取密钥和首次单篇验收的逐步说明见[配置页](https://jimmy-ui456.github.io/bioscope-daily/setup.html#models)。按2026-11-13官方北京地域短文本价格（输入0.2元/百万Token、输出0.8元/百万Token），每日20篇、每篇约2000输入/3000输出Token，30天约1.68元，仅为用量示例，实际按[当期价格](https://help.aliyun.com/zh/model-studio/model-pricing)结算。

服务需要支持 JSON 模式。字段不完整时采集继续运行，模型调用跳过。密钥不会写入网页、公开快照或浏览器存储。

排查配置可在[只查询模型目录的工作流](https://github.com/Jimmy-ui456/bioscope-daily/actions/workflows/model-diagnostics.yml)手动运行检查；只做一次官方目录GET，不生成文本，也不证明生成权限、余额或翻译质量。请求失败后新回执只保存固定失败分类及受控HTTP状态码，不保存原始响应或错误文本。供应商审计入口为百炼控制台 → 运维管理 → 模型监控 → 目标模型的查看日志 → 审计日志，参见[官方说明](https://help.aliyun.com/zh/model-studio/model-telemetry/)；无需开通推理日志或日志投递。

自动任务生成中文题名、完整中文摘要，以及附有逐字英文依据的研究问题、方法、结果与摘要明确报告的局限。后台按完整原摘要生成带编号的原文片段，模型选择编号，后台从本次输入还原原文，再走原有逐字检查；不做模糊匹配或改写英文。片段编号只减少抄写错误，不证明中文结论已获原文支持，仍需人工核对。未知编号或其他无效证据拒绝发布；没有摘要的记录不生成研究解读。

详情、日报页面和Markdown导出共用原文证据校验，导入备份后也会重新检查。无效论述会被隐藏并提示，合法辅助译文仍保留。证据可核对题名或摘要的连续原文与前后文，日报和导出同时保留有效局限及引文。逐字匹配不等于中文结论已经核实，仍需结合上下文和全文判断。

原型附带56篇真实文献的辅助中文译文，包括2026-10-29首期公共日报的10篇、2026-11-12公共日报的6篇及首个拥有PLOS下载统计的PrimeStack条目，尚未由领域专家审核。新文献未配置模型时显示“待翻译”。译文保存完整英文题名和摘要，并按版本精确匹配。新原文不会套用旧译文；保留的旧版译文仍可供相同英文的历史快照使用。目录分别记录独立文献数和原文版本数。发现接口摘要截断或原接口内数值差异时，页面和Markdown会保留与该英文版本绑定的来源提示，只翻译实际返回片段，不补造缺失阈值或结论。译文不是事实核验，自动解读仅基于摘要，不代表读取全文或验证研究结论。

默认不重复付费处理已有有效译文；需要对辅助译文补模型解读时，明确将 `config/monitor.json` 的 `interpretTranslatedPapers` 设为 `true`。定时每次最多10篇、每天最多20次请求，手动单篇验收最多1次；异常或缺失的既有预算会阻止付费，不按0重置。请求先记录回执再调用；结果未知或失败的请求不会自动重试。v2证据协议也检查v1旧请求键，升级不会绕过已有回执。管理员核对供应商记录后，才能决定是否从快照的 receipts 中清除对应失败记录以重试。平台故障、任务在保存前被强制终止等情况下不能保证绝对不重复计费。

## 文献下载量

仅使用**原出版平台的逐篇下载量**，不以引用量、浏览量、本站点击或平台总下载量替代。

- 支持 Zenodo 原论文记录的公开 API 下载统计，核对 DOI 与资源类型。统计含义为该论文记录的文件下载，不冒充单独 PDF 下载；不将关联数据集或补充材料统计归到另一篇论文。
- 支持 PLOS 官方逐篇使用接口，仅累计明确的 `get-pdf` 月计数，忽略混合使用量 `total`、HTML 和 XML 访问；展示统计覆盖说明。缺少部分月份 PDF 字段的记录不参与完整累计排行。原始论文进入监控范围后自动适配，不用无关旧论文填充榜单。
- 支持将有授权的出版社导出记录放入 `config/download-metrics.json`，包含 DOI、次数、平台、PDF/文件类型、累计/期间、出处和采集时间。
- 不同平台、类型与窗口分别排名；缺失值不作0、不参与排名。已知撤稿记录不进入下载排行，仍可在文献库核对来源。
- 导出统计的DOI与论文编号若同时提供，必须都与本篇一致；冲突标识、无效日历日期或缺失月份字段不能进入完整排行。
- Europe PMC 不返回逐篇下载量；PMC 逐篇使用报告需要出版社权限；bioRxiv 公开 usage 接口是平台总量，不能用于逐篇排名。

逐篇刷新单独记录成功、接口失败、未返回有效统计和受批次上限限制而未请求的状态，详情及榜单显示已有刷新记录。每轮最多请求20篇，优先尚未请求过或最久未请求的文献，避免列表后部长期无法更新；批次跳过不会清除历史尝试时间。接口失败时保留原计数及原采集时间，没有历史计数时保持未知；不会把本次文献采集成功等同于每篇下载量已更新。旧快照没有刷新记录时不反推结果。后台快照与Actions摘要同时保存受支持记录、已请求、有效返回、失败、无有效返回和本批未请求的文献篇数；这些是刷新记录数量，不是下载次数。缺少运行级汇总时保持未记录，不默认全成功或0。

当前文献可能没有下载数据。配置格式和官方说明见网页 `setup.html#downloads`。

排行与论文详情显示已知计数月份、缺报说明和采集时间。平台在首末报告月份之间完全漏报某月时，保留已知次数，但不将空月当0或加入完整累计排行。旧记录没有明确范围时如实注明未提供；仅有日期的记录不会虚构具体时间。累计下载量受发表时长影响，不代表统一近7日热度。

## 日报与数据

“每日简报”现在包含公共自动日报与个人手动精选简报。公共日报随后台采集生成，按近7个北京日历日、发表日期和主题覆盖轮取最多10篇，明确标为自动文献清单，不是人工科研价值精选。按主题分节，同日首次成刊后不重写，历史保留14个日历日。新访客无需先收藏论文即可阅读；没有符合规则的文献时如实显示空刊。

新成刊快照同时冻结采集触发方式、对应运行和未更新方向，页面与Markdown均保留。历史首刊缺少这些信息时保持未知，不能用后来一次成功补采倒推首刊完整。Actions发布成功也不等于所有方向都已更新，部分失败会在运行摘要和页面明确提示。

公开日报可通过 [RSS订阅](https://jimmy-ui456.github.io/bioscope-daily/feed.xml)。将地址粘贴到自己的RSS阅读器即可；每期有稳定的分享网址和GUID。订阅仅分发规则、题名与论文原文链接，不转载论文摘要/全文或个人收藏。历史期次超出保留范围时页面会明确提示。

公共档案逐期校验身份、日期、文献和分节；损坏期次整期跳过并告知数量，不删掉单篇后冒充完整首刊。读取失败或部分无效时保留上次已校验的可用期次，区分“未能读取”与合法空档案。页面会在后台周期中重试，也可在每日简报里单独重读档案；无需重新采集，不调用模型。所请求期次未读到且档案读取异常时，不直接推断为已过期。

按用户人工精选，取配置日期窗口内最新的最多10篇生成简报快照，最多保存14份。查看时可匹配相同原文版本的辅助译文；Markdown 同时保留中文、英文、出处与已有模型解读。浏览器打印可保存 PDF。

个人备份导入会先完成文献、身份映射及日报的校验与合并，再更新页面状态。整体备份无效时保持原状态；无效日报逐项跳过并提示数量，检查真实日期、日期窗口与生成时间，已有同ID快照优先保留。导入独有的论文在刷新及后续共享库更新后继续保留，仍受500篇上限约束；普通原型样本不会因此混入采集结果。切换到样本前会保存当前库供恢复，保存失败时保留当前内容。浏览器存储空间不足时仍可能只保留当前页面内容，请保存原备份。

每方向每次最多采集50条，文献库上限500条；身份按 DOI、PMID 和平台编号合并。7天表示北京日历 D-6 至 D，不是逐小时滚动窗口。尚未完成完整的跨 DOI 版本关联和更正撤稿追踪。

已知撤稿信号不会被后续来源缺少撤稿字段的记录覆盖。公共与个人日报、详情提示和后台模型跳过共用判断，兼容明确的中英文撤稿类型；题名提及撤稿或“未发现撤稿”等否定表述不作为已知撤稿。备份中的撤稿和预印本标志仅接受布尔值。历史日报和Markdown会按当前文献库的同一DOI、PMID或记录ID附加已知撤稿提示，保留原刊内容；这不是全面撤稿监测服务。不真实的日历日期视为未知，避免错误归入日报。

研究雷达可组合筛选期刊、北京日期、内容类型与摘要可用性；搜索支持题名、关键词、作者、期刊及有效中文译文，也可输入完整DOI、doi:前缀、DOI链接、PMID:编号或PubMed链接。标识查询按对应编号匹配，普通数字保留原文字段搜索；解析链接不触发访问或采集，结果仍受现有筛选条件限制。页面显示实际译文覆盖数、当前文献库更新时间和最近后台完成时间。

收藏页保留当前库中所有已收藏论文，不随关注方向关闭而隐藏。中文输入法确认候选文字前不会触发搜索导航，避免正在组合的输入被页面重绘打断。

后台状态区分本地正在运行、失败、部分完成、共享库读取失败和较旧快照。快照超过36小时未更新会提示核查，不直接断言云端任务失败。公开网站只能读取已发布的快照，最新云端排队或失败需通过页面提供的Actions运行记录确认。本地状态定期刷新；日报和RSS保存完成后才记录本次后台完成时间。

## 故障恢复

网页启动时检查本机文献缓存、收藏、精选、个人简报和偏好设置。异常记录不会阻断整站阅读：保留可读内容，坏简报整期跳过，并单独显示本机恢复提示。收藏编号不因论文暂未载入而删除。异常原始记录暂不自动覆盖，可先导出原始副本，再明确选择用当前恢复内容替换；其他页面已改动的记录会保留，提示重新核对。原始恢复副本与常规可导入备份格式不同，请妥善保留。恢复失败或存储空间不足时，当前页面仍可阅读，但不能声称新内容已经保存。这些本机问题不代表云端采集失败。

本地任务锁仅在确认同一主机的原进程已退出后自动恢复，活跃、跨主机或损坏的锁不会擅自移除。恢复动作本身若被强制终止，残留 `.recovery` 文件仍需管理员核查。状态文件损坏时状态接口会安全降级，不让网页服务随之退出。可解析但结构错误的调度状态（例如null、数组或错误类型的次数）也会告警；定时器保留原文件并停止该次处理，供人工核查，不通过清空记录绕过任务或重试限制。

本地部分方向采集失败时保留成功数据并有限重试。云端提交快照前会同步远端并rebase；冲突会明确失败，不强制覆盖。失败时尝试将 `library.json` 与公开日报保存在 Actions 的恢复附件中。启用付费模型后若发生保存或推送失败，应先检查这些附件、恢复预算和请求回执，再决定是否重跑；平台强制终止等情形仍不能保证请求结果完整持久化。

## 文件与检查

`dist/` 为网页及公开快照；`backend/` 为采集、解读、指标和本地调度；`config/` 为主题、预算和数据源配置；`.github/workflows/` 为测试、后台定时和发布流程。`.env`、`.data/`、`.cache/` 与 `.openai/` 均不提交。

```powershell
npm.cmd run check
npm.cmd test
```

更改版本或新增浏览器模块后运行 `npm run assets`，同步页面入口、样式及模块依赖版本。发布检查会拒绝未同步的资源，避免浏览器缓存混用新旧模块。

离线测试覆盖去重、分页、译文匹配、证据校验、调用上限与回执、日期、未知下载量、来源分组和异常保留。模型接入已准备，待维护者在Secrets填入自己的密钥并完成单篇验收；不能宣称真实模型服务已实测可用。
